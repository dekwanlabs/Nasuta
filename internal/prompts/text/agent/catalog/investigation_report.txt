Return exactly one JSON object with only:
- "focus": "{{ .Focus }}"
- "summary": concise evidence-based summary
- "findings": array of {"claim": string, "entity_ids": [exact task entity IDs directly supported by this finding], "evidence_goal_ids": [required facet strings], "evidence": [{"kind": string, "reference": string, "summary": string, "evidence_id": optional canonical handle, "identity": optional canonical identity}], "confidence": number from 0 to 1}
- "gaps": array of strings
- "covered_evidence_goals": required facet strings supported by at least one concrete finding
- "unresolved_evidence_goals": every remaining required facet string

- "discovered_dependencies": optional {"from","to","kind"} edges; omit when none were found
- "flow": optional compact process/architecture handoff with {"subject": string, "status": "complete"|"partial", "nodes": [{"id": string, "label": string, "kind": string, "evidence_refs": [references]}], "edges": [{"from": node ID, "to": node ID, "protocol": optional string, "sync_mode": "sync"|"async"|"unknown", "evidence_refs": [references], "evidence_state": "verified"|"inferred"|"unresolved"}], "open_hops": [unconfirmed transitions], "confidence": "low"|"medium"|"high"}

The workflow task directive supplies the exact required facet strings. Partition every required facet into exactly one of covered_evidence_goals or unresolved_evidence_goals. Every covered goal must appear in evidence_goal_ids on a finding backed by concrete task-contract seed material or tool-returned evidence. Tool results may include a `_nasuta_evidence_manifest`. Cite its `evidence_id` exactly in the matching evidence item; this is preferred over manually copying an identity. `identity` is only a canonical object with source_kind, target, and optional section/version/time_range. Never put a service UUID, serviceKey, document ID, or other plain string in `identity`; omit identity when you have an evidence_id or only a reference. Never invent, normalize, or broaden an evidence ID or identity. When the task contract names subjects, set `entity_ids` to those exact IDs and split findings when one claim is not supported for the same entity set. When the task contract has no entities, put newly identified user-facing business names in `discovered_entities` and repeat those same names in `findings.entity_ids`. Prefer fewer complete findings over an exhaustive response that risks truncating the JSON object. Return at most eight findings; each claim is one sentence. Put unsupported conclusions and unavailable evidence in gaps. Do not return markdown or text outside the JSON object.

If the objective asks for a process, architecture, request path, or business flow, include exactly one compact `flow` object. Keep it to the primary path and at most six hops: do not emit a complete API inventory. Every node must represent a responsibility or system boundary. Mark an edge `verified` only when its `evidence_refs` point to real evidence supplied to this child; otherwise use `inferred` or `unresolved`. Missing transitions belong in `open_hops`. Keep protocol and sync mode when directly observed, and use `unknown` rather than guessing. A flow is a handoff artifact, not a replacement for evidence-backed findings.
