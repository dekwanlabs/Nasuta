Suggest whether the current request benefits from one agent or a fixed read-only multi-agent investigation workflow.
- strategy must be single_agent or multi_agent.
- complexity measures structural complexity from 0 to 1.
- confidence measures confidence in the execution suggestion from 0 to 1.
- Recommend multi_agent only when at least two distinct investigation deliverables can start immediately, remain useful if the other tasks fail, and be merged deterministically.
- A task is a user-visible investigation objective, not an evidence source, service, repository, tool, facet, retrieval branch, or result hit.
- Multiple sources, services, repositories, tools, facets, or retrieval hits for one objective are still one task.
- For single_agent, tasks must be [].
- For multi_agent, tasks must contain 2 to 4 unique tasks. Every task must set independently_useful=true and depends_on=[].
- Task ids must be unique canonical lowercase ids. Objectives must be distinct and no longer than 500 characters.
- Consider distinct deliverables, uncertainty, risk, independent validation, and whether work can begin in parallel.
- Do not recommend multi_agent merely because a request is technical, long, or asks for internal evidence.
- Evidence source selection and execution strategy are independent. Explicit evidence sources constrain sources but do not force multi_agent.
- reasons contains at most 4 unique codes selected only from: requires_multiple_subproblems, requires_cross_source_analysis, requires_cross_service_analysis, requires_independent_evidence_validation, requires_conflict_resolution, requires_risk_sensitive_analysis, supports_parallel_investigation, single_focused_question, single_source_sufficient, subproblems_are_sequential, provided_context_sufficient.
- Never return agent IDs, workflow IDs, providers, permissions, tool grants, or parallelism.
Return a JSON object with this exact shape. complexity and confidence are real estimates for THIS request (never 0), and reasons is non-empty:

- multi_agent: {"execution":{"strategy":"multi_agent","complexity":0.7,"confidence":0.8,"tasks":[{"id":"business_design","objective":"Establish the business workflow and responsibility boundaries.","independently_useful":true,"depends_on":[]},{"id":"implementation","objective":"Verify the implementation path and state transitions in code.","independently_useful":true,"depends_on":[]}],"reasons":["requires_multiple_subproblems","supports_parallel_investigation"]}}
